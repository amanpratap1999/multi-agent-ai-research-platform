## 1. Problem Statement

Autonomous multi-agent research pipelines are notoriously vulnerable to prompt injection, high operational latency, escalating LLM costs from redundant research tasks, and hallucinated or unverified conclusions. Furthermore, when deploying multi-agent systems to production, enterprise teams struggle with:
1. **Adversarial Fragility**: Scraping untrusted web text exposes agent pipelines to Cross-Domain Prompt Injection (XPIA) and multi-turn jailbreaks (Crescendo, Skeleton Key) that can hijack downstream summarization and report generation.
2. **Redundant Computation & Skyrocketing Costs**: Repeated or semantically similar research queries waste full multi-turn model context and API spend instead of instantly returning cached verified findings.
3. **Fragile Single-Provider Dependency**: Relying on a single LLM API causes downtime and latency spikes when outages occur.
4. **Disconnection Between Offensive and Defensive Tooling**: Red teaming is typically done in isolated offline spreadsheets or batch notebooks, disconnected from runtime guardrails and live telemetry.

This project delivers a **production-grade, defensible autonomous research platform** that solves these challenges end-to-end: a 4-agent LangGraph pipeline protected by dual-boundary AWS Bedrock Guardrails, load-balanced and failover-routed via a high-performance TensorZero gateway, accelerated by a 3-tier memory system (Redis STM, semantic caching, and pgvector LTM), and continuously stress-tested by an integrated PyRIT adversarial attack harness with a live War Room telemetry dashboard.

## 4. Key Subsystem Specifications

### 4.1 LangGraph 4-Agent Pipeline
State schema is defined via strongly typed Pydantic models:
```python
from typing import List, Dict, Any, Optional
from typing_extensions import TypedDict

class ClaimAudit(TypedDict):
    claim: str
    citation_url: str
    verdict: str  # "SUPPORTED" | "CONTRADICTED" | "UNVERIFIED"
    quoted_evidence: str

class ResearchState(TypedDict):
    topic: str
    session_id: str
    search_queries: List[str]
    raw_sources: List[Dict[str, Any]]
    scrubbed_sources: List[Dict[str, Any]]
    quarantined_sources: List[Dict[str, Any]]
    summary: str
    draft_report: str
    claims_audit: List[ClaimAudit]
    verification_feedback: str
    verification_score: float  # count(SUPPORTED) / total_claims
    iteration_count: int
    is_degraded: bool
    final_report: Dict[str, Any]
    defense_telemetry: List[Dict[str, Any]]
```

#### Node Execution Details:
1. **Search Agent**:
   - Generates targeted queries and fetches raw web text via DuckDuckGo (zero-key local default) or Tavily.
   - **Text Normalization & Chunking**: Strips HTML tags and splits long pages into maximum 3,000-character snippet windows (strictly enforcing Bedrock's 25,000-character API ceiling).
   - **XPIA Quarantine Gate**: Evaluates snippets concurrently via Bedrock `ApplyGuardrail` (`asyncio.Semaphore(5)`). Any snippet triggering prompt attack detection is **quarantined and discarded**; safe snippets pass into `scrubbed_sources`.
2. **Summarize Agent**: Synthesizes verified snippets into structured thematic outlines, preserving source URLs and timestamps.
3. **Write Agent**: Composes a publication-grade report with Executive Summary, Technical Analysis, Risk Factors, and Reference Citations. Exports to Markdown, JSON, and PDF (via `weasyprint`).
4. **Verify Agent & Deterministic Loopback Routing**:
   - Audits factual claims against cited text using a structured `ClaimAudit` schema.
   - Computes citation fidelity score: $\text{score} = \frac{\text{count(SUPPORTED)}}{\text{total\_claims}}$.
   - **Routing Rules**:
     - If `score >= 0.85`: routes directly to `egress_guardrail`.
     - If `score < 0.85` and `iteration_count < 2`: increments iteration count and routes back to `write_agent` (or `search_agent` if source evidence was insufficient).
     - If `score < 0.85` and `iteration_count >= 2`: routes to `degraded_export`, injecting a prominent `[CRITICAL_UNVERIFIED_WARNING]` warning banner into the report while preserving full audit details.

### 4.2 AWS Bedrock Guardrails (Dual-Boundary Defense)
- **Ingress Perimeter**: Evaluates user input against:
  - Prompt Attack Detection (Jailbreak / Direct Injection filters).
  - Denied Topics policy (e.g. malicious exploit payload generation, unauthorized financial/legal advice).
  - PII Detection & Redaction (credit cards, social security numbers, API tokens).
- **Untrusted Source Perimeter (XPIA Protection)**: Evaluates scraped external web pages against indirect injection signatures. Malicious payloads are quarantined.
- **Egress Perimeter**: Evaluates final synthesized reports for sensitive information leakage and hallucinations.
- **Local Boto3 Mock Engine**: For local Docker execution without AWS credentials, a high-fidelity mock implements the exact `ApplyGuardrailResponseTypeDef` Boto3 schema:
  `{"action": "NONE" | "GUARDRAIL_INTERVENED", "outputs": [{"text": str}], "assessments": [...]}`.

### 4.3 TensorZero LLM Gateway
- High-performance gateway handling model failover, load balancing, and telemetry.
- Routing hierarchy defined in `tensorzero.toml`:
  1. Default: `gpt-4o` (high reasoning capability for synthesis and verification).
  2. Fallback 1: `groq/llama-3.3-70b-versatile` (instant millisecond failover upon rate-limit or timeout).
  3. Fallback 2: `bedrock/anthropic.claude-3-5-sonnet` (AWS native fallback).
- In-process fallback: When running in lightweight local dev mode without the TensorZero Docker container, an in-process adapter (LiteLLM) handles identical fallback mechanics.

### 4.4 Three-Tier Memory & Caching Architecture
- **Tier 1: Short-Term Memory (STM - Redis)**: Stores ephemeral LangGraph checkpointer state, agent scratchpads, and pub/sub channels for the SSE telemetry feed.
- **Tier 2: Semantic Cache (Redis with Vector Search)**:
  - **Local ONNX Embedding**: Uses in-process `fastembed` (`all-MiniLM-L6-v2` ONNX) to vectorize queries in 4–8ms, guaranteeing true $<15\text{ms}$ cache lookup.
  - **Read Gate**: If cosine similarity $\ge 0.92$, the entire multi-agent pipeline is bypassed and the cached verified report is returned instantly.
  - **Write Gate**: Only reports with `verification_score >= 0.90` and `is_degraded == False` are indexed into the semantic cache.
  - **TTL & Invalidation**: Default TTL of 72 hours; support `X-Bypass-Cache: true` header to force fresh research.
- **Tier 3: Long-Term Memory (LTM - PostgreSQL with `pgvector`)**: Stores durable relational data, full historical report archives, citation graphs, user metadata, and historical PyRIT red team audit logs.

### 4.5 PyRIT Adversarial Red Teaming Harness
- **Attacks Supported**:
  1. **Direct Jailbreak**: Standard adversarial prompt injection converters (Base64 encoding, ROT13, suffix attacks).
  2. **XPIA (Cross-Domain Prompt Injection)**: Simulates compromised web search results containing embedded instructions to exfiltrate session data.
  3. **Crescendo Attack**: Multi-turn conversational attack engine that starts with benign queries and incrementally nudges the agent to bypass guardrails over 4-8 turns.
  4. **Skeleton Key Attack**: Multi-turn prompt strategy that masquerades as an authorized security researcher or system admin requesting override of safety protocols.
- **Asynchronous Execution Pattern**:
  - Because multi-turn attacks (e.g. 6-turn Crescendo) run 120–180s, runs are decoupled from synchronous HTTP requests.
  - `POST /api/v1/redteam/campaigns` creates a background task in `pyrit-worker` and returns `202 Accepted` with a `campaign_id`.
  - Frontend listens on `GET /api/v1/redteam/stream/{campaign_id}` receiving Server-Sent Events emitted via Redis Pub/Sub with periodic `: ping` heartbeats.

### 4.6 Standardized SSE Telemetry Packet Protocol
All streaming endpoints broadcast structured SSE packets:
- `event: node_transition` -> `{"session_id": "...", "node": "summarize", "status": "running", "timestamp": "..."}`
- `event: guardrail_event` -> `{"boundary": "xpia", "action": "BLOCKED", "policy": "PROMPT_ATTACK", "latency_ms": 82, "quarantined_snippet_id": "src-4"}`
- `event: pyrit_turn` -> `{"campaign_id": "...", "turn": 3, "attack": "crescendo", "prompt": "...", "verdict": "BLOCKED", "latency_ms": 115}`

### 4.7 Frontend Architecture (Adversarial War Room UI)
- To guarantee **1-command zero-node local simplicity**, the War Room dashboard is served directly by FastAPI using modern Tailwind CSS + Vanilla JS/Alpine.js SPA templates from `/static` and `/templates`.
- Eliminates Node.js container orchestration headaches while delivering responsive dark-mode cyber range visuals, live SSE connection handling, and interactive split-screen attack telemetry.

### 4.8 Infrastructure & Deployment Parity
- **Local Parity (`docker-compose.yml`)**:
  - `web`: FastAPI application (agents, War Room UI, REST, SSE).
  - `redis`: Redis Stack (vector search enabled).
  - `postgres`: PostgreSQL 16 with `pgvector`.
  - `tensorzero`: TensorZero Gateway container.
  - `pyrit-worker`: Background red-team attack runner.
- **Cloud Infrastructure (Terraform on AWS)**:
  - Modular Terraform: `vpc`, `ecs`, `rds` (Aurora Serverless v2 + pgvector), `elasticache` (Redis), `bedrock` (Guardrails), and `eventbridge`.
  - Cost Optimization: Pre-configured single-AZ dev profile to avoid unnecessary idle NAT Gateway costs ($32/mo) during portfolio demonstration.
  - Automated weekly EventBridge rule executes headless PyRIT regression test and archives results to PostgreSQL.
  - GitHub Actions CI pipeline runs linting, unit tests, integration tests, and `terraform validate`.

## 5. Constraints

1. **Dual-Target Parity**: Any feature implemented must execute cleanly in local Docker Compose without requiring live AWS credentials, using intelligent local mocks/fallbacks when AWS Bedrock keys are absent.
2. **Sub-Second Guardrail Latency**: AWS Bedrock `ApplyGuardrail` calls must add $<150\text{ms}$ latency overhead to request ingress.
3. **Deterministic State Isolation**: Agent nodes must never mutate global state directly; all data passes through typed LangGraph state updates.
4. **Zero Untrusted Scraping Leakage**: External web search scraping must be sanitized before tokenization in LLM context windows.

## 6. Agreed Premises

1. **Deterministic Agent Pipeline with LangGraph**: Search, Summarize, Write, and Verify operate as distinct, state-gated LangGraph nodes with typed schemas, independent retry logic, and strict citation tracking.
2. **Dual-Boundary Defense & Untrusted Search Scrubbing**: Bedrock Guardrails intercept both user ingress and report egress, while PyRIT tests the system against external XPIA payloads scraped by the Search agent.
3. **Three-Tier Memory & Semantic Cache Interception**: Redis handles fast STM and millisecond semantic caching (cosine similarity threshold $\ge 0.92$), while PostgreSQL with `pgvector` stores durable LTM knowledge and historical reports.
4. **Hybrid Dual-Target Infrastructure Parity**: The codebase provides a single-command `docker compose up` local setup alongside production AWS Terraform modules deployed via GitHub Actions.

## 8. Approaches Considered

### Approach A: The Full Autonomous Fortress (Selected)
- **Summary**: End-to-end implementation of the complete architecture: 4-agent LangGraph pipeline, Bedrock Guardrails, TensorZero gateway with Groq/GPT-4o fallback, 3-tier memory (Redis STM/Cache + pgvector LTM), PyRIT War Room dashboard with SSE streaming, LangSmith judge, Terraform AWS infra, and GitHub Actions CI/CD.
- **Effort**: L (human: ~2-3 weeks / CC: ~2-3 hours)
- **Risk**: Med (multi-service integration surface)
- **Pros**: Complete fidelity to user diagram, zero compromises, dual Docker/Terraform parity.
- **Cons**: Highest number of interlocking components to coordinate.

### Approach B: The Staged Cyber Range
- **Summary**: Focuses purely on the live PyRIT attack War Room and 2-stage LangGraph pipeline in Phase 1, deferring pgvector LTM and Terraform AWS modules to Phase 2.
- **Effort**: M (human: ~1 week / CC: ~45 min)
- **Risk**: Low
- **Pros**: Rapid time-to-first-wow in browser.
- **Cons**: Leaves out enterprise cloud infrastructure and vector database mastery initially.

### Approach C: The Self-Immunizing Range
- **Summary**: Builds Approach A plus an autonomous "Blue SRE" agent that automatically synthesizes Bedrock Guardrail policy updates and prompt filters when a PyRIT attack bypasses defenses.
- **Effort**: XL (human: ~4 weeks / CC: ~4 hours)
- **Risk**: High (runtime policy synthesis and dynamic Bedrock API mutations)
- **Pros**: Extreme novelty; self-healing defense loop.
- **Cons**: Adds significant orchestrator complexity.

## 10. Open Questions & Design Decisions (Settled)

1. **Search Provider Defaults**: Standardized on DuckDuckGo (zero-key local default) with clean configuration switch for Tavily. (Exa dropped per YAGNI review).
2. **Bedrock Local Mocking**: Standardized on full Boto3 `ApplyGuardrailResponseTypeDef` schema compatibility for zero-credential local runs.
3. **Semantic Cache Embeddings**: Standardized on in-process ONNX embeddings (`fastembed`) for true $<15\text{ms}$ cache lookup.
4. **PyRIT Asynchronous Streaming**: Standardized on `202 Accepted` + Redis Pub/Sub SSE feed to eliminate 60s HTTP gateway timeouts.
5. **War Room UI Packaging**: Standardized on FastAPI static/Jinja templates (Tailwind CSS + Alpine.js) to avoid extra Node.js container bloat.
